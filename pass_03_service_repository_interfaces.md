## Repository interface pattern

```python
class BaseRepository(Protocol[T]):
    async def get_by_id(self, id: UUID) -> T | None: ...
    async def list(self, *, limit: int = 50, offset: int = 0) -> list[T]: ...
    async def add(self, obj: T) -> T: ...
    async def update(self, obj: T) -> T: ...
    async def delete(self, id: UUID) -> None: ...
```

### Concrete repository responsibilities

- `UserRepository` — `user_account` and `person` lifecycle
- `RelationshipRepository` — edge retrieval, confirmation states, and graph traversal helper methods
- `InvitationRepository` — invites and QR/link generation metadata
- `NotificationRepository` — unread count and notifications
- `PrivacyRepository` — field-level visibility settings
- `SearchRepository` — fuzzy name lookup, matching, and discovery queries
- `TreeRepository` — recursive CTE queries and graph traversal helpers

## Data access rules

- All relationship labels are computed at query time.
- `relationship_edge` is the single source of truth.
- Repository methods should return DTO-like results, not label-bearing domain objects.
- Pagination is enforced in query layer for tree expansion and search results.
